The Portal is where an incursion or standard event is created and viewed. Each time slot has a Google Calendar entry,
and the linked Zoho deal holds the booking details and session times.

## Creating an event

<Steps>
  <ol>
    <li>
      <h3>Enter the shared booking details</h3>
      <p>
        The Portal collects the event and organisation, contact details, studio, address, price, notes, invoice link, and
        event type. Incursions also include their module and expected students per session.
      </p>
    </li>
    <li>
      <h3>Add one or more time slots</h3>
      <p>
        Multiple sessions entered together become sibling slots under one event. They share the same booking details but
        each keeps its own start time, end time, Portal slot ID, and Google Calendar event ID.
      </p>
    </li>
    <li>
      <h3>The Portal creates Google Calendar entries</h3>
      <p>
        Each slot becomes a separate entry on the Events calendar using the event name, address, times, and internal
        notes. The resulting calendar ID is saved back to that Portal slot.
      </p>
    </li>
    <li>
      <h3>The Zoho deal is updated</h3>
      <p>
        The linked business deal is confirmed or created with the booking details and all session times.
      </p>
    </li>
    <li>
      <h3>An optional confirmation is sent</h3>
      <p>
        If selected, the customer receives a confirmation containing all slots, the address, price, and staff-written
        email message. Incursion confirmations also identify the chosen module.
      </p>
    </li>
  </ol>
</Steps>

<Aside type="note" title="Sibling slots are connected, not duplicates">
  Contact details, organisation, address, event name, price, notes, and other shared fields belong to the whole booking.
  Dates, times, and calendar IDs belong to each slot.
</Aside>

## What edits change

<CardGrid>
  <Card title="Shared details" icon="puzzle">
    Editing one sibling updates the shared Portal fields on every slot. The system also updates each Google Calendar
    entry with those shared details while preserving each sibling's own times.
  </Card>
  <Card title="Selected slot times" icon="calendar">
    The start and end time being edited apply to that slot only. Other sibling sessions keep their existing dates and
    times.
  </Card>
  <Card title="Linked Zoho deal" icon="rocket">
    Editing a linked booking updates the deal using all current sibling slots.
  </Card>
  <Card title="Deleting a slot" icon="warning">
    Deleting removes that Portal slot and its Google Calendar entry and adjusts the linked Zoho sessions. Deleting the
    final slot also removes the parent event record.
  </Card>
</CardGrid>
